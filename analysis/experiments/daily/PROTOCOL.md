# Protocol for the daily single-query extension

For each of the five archived input files, time explicit pair enumeration and exact-only endpoint aggregation at 3,600 s and 86,400 s. Use the released timestamp origin, remove self-contacts, keep multiplicity and use weights of one. Each primary timing covers every occupied bucket of that trace at that width. For CollegeMsg and Email EU also time the single day with the most eligible pairs, and the single day with the most eligible pairs per event, selecting the earliest day in a tie. Report when the two selections coincide. Isolate selection cost from execution.

Use the designated Linux experiment server in one sequential session, pinning the worker to one logical CPU. Record kernel, Python, CPU and elapsed time, process scheduling delay and sibling activity. Load, sort, form buckets and choose the selected days before timing. For each workload run one untimed warm-up pair and twelve timed pairs, alternating which method runs first. Retain every elapsed time and execution position. Both methods must reproduce each bucket's integer pair count and 12 times its variance in every trial. Record summed outputs and workload sizes for independent comparison with the structural results. Report the median and inclusive first and third quartiles. Compute execution speed ratios using unrounded medians. Fixed observed input is the only benchmark input; this experiment uses no pseudorandom samples.
